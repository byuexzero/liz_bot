# 已移除功能：舞萌发包（`/qr` 扫码查询）

**移除时间**：2026-09-22
**移除原因**：按要求暂时下线机器人对舞萌服务端的发包功能。

本文件记录被移除的全部代码与恢复步骤，方便随时还原。

---

## 移除了什么

机器人里对舞萌服务端的**发包只有一处**：`/qr` 指令会把玩家扫卡的二维码
POST 到 `ai.sys-allnet.cn` 换取 `userId` 与 `token`。

移除涉及 3 个文件：

| 文件 | 移除内容 |
|---|---|
| `liz_bot/daily_funcs.py` | `qr_reply()` 函数、`import httpx`、`from maimai.qr import ...` |
| `liz_bot/command_router.py` | `handle_command()` 里的 `/qr` 分发分支 |
| `liz_bot/command_handler.py` | facade 中对 `qr_reply` 的再导出与 `__all__` 条目 |

### 未受影响的部分

- **`maimai/` 包本身完好** —— `maimai.qr` 的 `qr_api` / `qr_api_async` / `parse_qr`
  全部保留。移除的只是机器人的**调用入口**，底层能力没有动。
- `pic_haddler.py`（上传媒体到腾讯）与 `qqgroup-ai-bot.py`（AI 对话）
  不属舞萌发包，保持原样。

### 行为变化

`/qr <二维码>` 现在会返回 `未知指令：qr`（走 `handle_command` 的兜底分支），
不再发起任何网络请求。

```python
def qr_reply(qr_code: str) -> str:
    """扫码查询，返回格式化结果。

    A.I.M.E. 接口的 errorID 语义：
        0  → 成功
        1  → 二维码已过期
        50 → 参数错误
    """
    reply = ""
    try:
        qr_data = qr_api(qr_code)
        if qr_data["errorID"] == 1:
            reply = "二维码已过期，Liz也做不到..."
        elif qr_data["errorID"] == 50:
            reply = "不要给Liz错误的参数..."
        elif qr_data["errorID"] == 0:
            for key in qr_data:
                reply += (f"\n{key}: {str(qr_data[key])}")
    except QrApiError as exc:
        # 网络错误、HTTP 非 200、响应非 JSON 都归到这里
        reply = f"扫码接口出错：{exc}"
    except httpx.HTTPError as exc:
        reply = f"网络异常：{exc}"
    return reply
```

## 恢复前请先确认

1. **`.env` 已就绪** —— `maimai.qr` 依赖 `CHIP_ID`、`AIME_SALT`、`AIME_QR_URL`，
   缺任一项会在导入期报错。
2. **二维码是活跃凭据** —— `/qr` 会把玩家二维码发给第三方服务
   （`ai.sys-allnet.cn`，非世嘉官方域名）。确认这是预期行为再恢复。
3. **`qr_api` 是同步的** —— 它被 `async` 的 `handle_command` 直接调用，
   **会阻塞整个事件循环**（QQ 机器人的其他消息在此期间无法处理）。
   若要恢复，建议改造成 `await qr_api_async(...)`：

   ```python
   from maimai.qr import qr_api_async

   async def qr_reply(qr_code: str) -> str:
       ...
       qr_data = await qr_api_async(qr_code)
       ...
   ```

   这样 `handle_command` 里也要相应改成 `return await daily_funcs.qr_reply(keyword)`。
